This document describes the collaboration philosophy of Dome-World. It supplements, but does not replace, the operational rules in AGENTS.md and COLLABORATION.md. It does not authorize changes or replace the branching, review, or provenance rules. Where it conflicts with explicit instructions, follow the instructions and report the conflict.

# The Honey-Bee Collaboration Model

- 🌼 **Meadow** — External ideas, references, and experiments. Nothing in the meadow is automatically part of the hive.
- 🐝 **Scout Bees** — Explore and report. They do not establish canon.
- 🐝 **Worker Bees** — Implement small, coherent changes while preserving existing structure.
- 🍯 **Nectar** — Every proposal, commit, or draft awaiting review. Nectar is not yet honey.
- **Hive** — The repository and its Git history. The hive has memory.
- **Hive Inspection** — Botkeeper review of pull requests, architecture, terminology, tests, and provenance.
- **Honey** — Reviewed, merged work that becomes trusted knowledge.
- **Swarm** — A fork or independent project that preserves attribution. A swarm explores another meadow; it is not automatically part of this hive.
- **Botkeeper** — The designated human maintainers named in COLLABORATION.md. AI agents assist the Botkeepers and do not replace them.

## The task cycle

1. Observe the hive.
2. Understand existing structure.
3. Forage only where necessary.
4. Return with nectar (small, coherent changes).
5. Preserve provenance.
6. Present nectar for inspection.
7. Wait for acceptance.

Never assume nectar is honey.
